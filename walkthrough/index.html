Start here

A paid lane for onchain data agents

Sellers publish a priced service at an ENSv2 subname where the resolver record is the offer. Buyers issue a mandate their agent spends inside but can never widen.

This walkthrough is for a judge with fifteen minutes and no intention of installing anything. Thirty minutes if you do want to run it. Page six is the whole of that: one docker compose up and three commands. Six pages, one idea each, in the order the system actually works. Every one of them ends with either a transaction you can open in a block explorer or a sentence saying we did not prove this.

Read it in order and you will have gone from “what problem is this” to a settled payment on two chains without leaving the browser. Read page three and page five only, and you will have found both of the places this project is weakest, because we put them on the page rather than making you look.

Not claimed

The hosted seller endpoint is not live. Nothing on the open internet will answer a paid request today.

Why
The ENS record agent-endpoint[mcp] names turnstile.moveseventyeight.com, which has no DNS record yet. The deploy is scheduled for 14 September 2026.
Consequence
A judge reading only the ENS record finds nothing to pay. The service is real and runs from the repo — page six runs it in one command.
Scope
This is a deployment gap, not a capability gap. The settlements linked from page four are real transactions on public testnets and are unaffected.

The six pages

  1. 01 The problem

    An agent selling onchain analysis cannot be discovered, cannot state a price you can read before calling it, and cannot sell an edge without publishing the method. A buyer cannot let an agent spend without handing it a key.

    Proves 197 real ERC-8004 registrations read; exactly one publishes a readable price

  2. 02 The offer record

    The ENSv2 subname is the offer. Price, rails and endpoint are resolved from Sepolia on every request — no cache, no hard-coded values, and standard ENSIP-25/26 keys rather than a schema we invented.

    Proves a resolver call you can rerun with cast

  3. 03 Three keys

    Cold, warm and hot, and what each one may authorise. The invariant the whole design defends: the key that spends can never raise its own limit.

    Proves the hot key’s setAddr reverting on live Sepolia · admits custody is not cold

  4. 04 Two rails

    The same query paid on Hedera and on Arc, answered identically both times. Sub-cent payments batch into one transaction, and the spending agent never submits one.

    Proves settled HBAR and USDC, and an agent nonce still at 0

  5. 05 Keep the method

    The analyst runs inside an enclave, so a buyer gets a verdict they can verify against a hash and cannot reproduce. Sell the answer, keep the method.

    Proves a byte-identical verdict settled on Sepolia · admits it is not DON-attested

  6. 06 Run it

    One docker compose up, three commands, and where each piece of the code lives. The shortest of them returns 402 Payment Required, which is the whole product in one line.

    Proves the thing on your own machine, in about fifteen minutes
